# 04 模块详设

> 前置：[03-架构与技术选型.md](03-架构与技术选型.md)。本文固化三类契约：**InvoiceCard schema**（模型层）、**解析字段映射**（解析层）、**检测规则表与存储 schema**（规则/存储层）。
> 契约变更纪律：本文是字段名/规则 ID 的权威出处；改动必须先改本文再改代码，并在 HANDOFF 既定口径登记。

## 1. InvoiceCard 发票参数卡（统一中间表示）

设计原则：字段-值-置信度-证据四元组；所有金额用 `Decimal`（分两级存 `str` 避免浮点误差）；证据记录来源与原文摘录，支撑异常判定可溯源。

```python
@dataclass
class Evidence:
    source_file: str          # 相对导入路径（不存绝对路径，防隐私泄露）
    quote: str                # 原文摘录（PDF 文本层片段 / XML 原始文本）
    location: str = ""        # 可选：页码/页码+坐标 或 XML 节点路径

@dataclass
class LineItem:               # 项目明细行
    name: str                 # 品名/项目名称
    amount: str               # 金额（不含税），Decimal 字符串
    tax_rate: str             # 税率，如 "0.13"
    tax_amount: str           # 税额，Decimal 字符串

@dataclass
class InvoiceCard:
    invoice_number: str       # 数电票 20 位号码（主键）
    invoice_type: str         # 数电普票/数电专票/电子普票/纸质专票/纸质普票
    issue_date: str           # 开票日期 YYYY-MM-DD
    buyer_name: str
    buyer_tax_id: str         # 统一社会信用代码（18 位，合成假格式）
    seller_name: str
    seller_tax_id: str
    items: List[LineItem]
    amount: str               # 合计金额（不含税）
    tax_amount: str           # 合计税额
    total_with_tax: str       # 价税合计
    total_with_tax_cn: str    # 价税合计大写
    remark: str = ""
    batch_id: str = ""        # 导入批次号（入库时填充）
    confidence: float = 1.0   # 整卡置信度；字段级低置信度进 field_flags
    field_flags: List[str] = field(default_factory=list)  # 如 ["remark#low_conf"]
    evidence: List[Evidence] = field(default_factory=list)
```

- **序列化**：`to_dict()/from_dict()` 往返一致（骨架已交付并测试）；真值 JSON 与基准对账都用同一 dict 形态。
- **空值语义**：解析不到的字段留空串 + 登记 `field_flags`，**不造默认值**（防幻觉）；必填主键（发票号码）缺失的文件整卡拒绝入库并记导入日志。

## 2. 解析层字段映射

### 2.1 XML 解析器（数电票数据电文，FR-02，亮点）

| 项 | 设计 |
|---|---|
| 加载 | `ElementTree.parse`；读 bytes 后按 UTF-8 解码；拒绝外部实体（stdlib 默认不解析外部 DTD，符合隐私/安全） |
| namespace | 数电票 XML 若带命名空间，用 `{ns}tag` 匹配；**映射表按"localname 优先 + ns 白名单"设计**，ns 不匹配时降级 localname 匹配并降置信度 |
| 字段映射 | 维护 `FIELD_MAP: dict[strPath, cardField]`（XML 节点路径 → InvoiceCard 字段），M1 定稿：生成器模板即权威映射，映射表落在 [data/samples/TEMPLATE_REFERENCE.md](../data/samples/TEMPLATE_REFERENCE.md)（官方样例查到后追加第二套映射并标注"待核对"） |
| 数值清洗 | 千分位逗号剥离、全角转半角、`¥`/`￥` 剥离；清洗后非合法 Decimal 即丢弃该值并降置信度（**数值超范围即丢弃**纪律） |
| 明细行 | 遍历 `<Items>` 类容器节点逐行构造 LineItem；行内字段缺失按空串+flag 处理 |
| 证据 | 每字段记录节点路径 + 原始文本（location=节点路径） |

### 2.2 PDF 解析器（版式文件文本层，FR-03）

| 项 | 设计 |
|---|---|
| 提取 | pdfplumber `extract_words()`（词级 + 坐标）；不依赖字符序 |
| label-slot | 标签词表（"发票号码"、"开票日期"、"价税合计"…）→ 右侧/下方邻近槽位取值：同 y 轴带内向右找最近词（多行值按 y/x 邻近聚类合并）；大写金额区（"价税合计（大写）"后）整行截取 |
| 已知陷阱 | 版式导出的伪空格（字符间手工定位空格）→ 匹配前剥离全部空白比对；标签跨行 → 标签词典带变体 |
| 数值区 | "金额"/"税额"/"合计"列按 x 坐标列聚类后逐行归并到明细 |
| 证据 | location=页码+词坐标区间；quote=文本层原文 |
| 失败语义 | 结构识别失败 → 抛 ParserError；单字段缺失 → 空串+flag；**不猜值** |

### 2.3 OFD 解析器（FR-04，P2）

zipfile 打开 → `OFD.xml` 定位文档结构 → 逐页 content XML 抽文本（结构同源 GB/T 33190）；字段映射复用 PDF 的 label-slot 逻辑（文本层语义一致）。进度风险首顺延项。

## 3. 检测规则表（规则引擎的机器可读契约）

> 引擎按 `rule_id` 分派 check 函数，参数来自配置（默认值如下）；Finding 结构：`{finding_id, rule_id, level, invoice_numbers[], message, evidence{}}`。
> **判定级别语义**：`error`=确认异常（确定性算术/键冲突）；`suspicious`=疑似（模糊/簇类启发）；`review`=待人工确认（低置信度、跨期临界）。

| 规则 ID | 名称 | 级别 | 逻辑要点 | 参数（默认） | 依据 |
|---|---|---|---|---|---|
| R-ARITH-01 | 价税合计复核 | error | Σ(明细金额)=amount 且 Σ(明细税额)=tax_amount 且 amount+tax_amount = total_with_tax（容差 0.01；明细字段缺失/空时对应子检查跳过，不硬判） | tolerance=0.01 | 票面算术自洽 |
| R-ARITH-02 | 大写金额一致 | error | total_with_tax 转中文大写 ≡ total_with_tax_cn；不可解析不硬判 → review | — | 票面自洽 |
| R-DUP-01 | 精确重复 | error | 本次导入集合内同号多卡，**或**号码已存在台账（ctx existing_numbers）；M3 定稿：入库与判重分离——引擎输入=全部解析卡（含入库被拒的同号副本），被拒副本仍参与判定 | — | 重复报销主形态 |
| R-DUP-02 | 联合键重复 | error | (号码, total_with_tax, issue_date) 完全相同且 batch_id/登记来源不同；**排除字段完全一致的纯复制件**（纯复制件由 R-DUP-01 完整覆盖——真值语义 M1 定稿，见 plan/05 §1.3 与生成器模块注释）。纯复制件判定口径：两卡语义字段全等，evidence/confidence/field_flags/batch_id 不参与比较（与解析对账口径一致） | — | 跨员工/跨批次再制票 |
| R-DUP-03 | 模糊重复 | suspicious | 同 seller_tax_id + 同 issue_date ± 窗口 + 金额差 ≤ 阈值（金额=价税合计，精确匹配档优先），排除已命中 R-DUP-01/02 的组合（同号副本同销售方同日同额不触发） | date_window=1d, amount_tol=0.00 | 近似重复需人工复核 |
| R-SEQ-01 | 连号拆分簇 | suspicious | 同 seller_tax_id 分组，发票号码后缀连续（≥min_len 张）且开票日期在窗口内；前缀不同只警示不判异常（M3 实现定稿：跨前缀不产出 finding，防误报） | suffix_len=8, min_len=3, date_window=7d | 连号拆分报销特征 |
| R-TIME-01 | 开票晚于导入 | error | issue_date > batch 导入日期（基准通路=批次 expense_anchor，M1 定稿；实际使用=导入时刻） | — | 时间逻辑 |
| R-TIME-02 | 跨期异常 | review | issue_date 与批次报销月份跨月超过 N 期（基准通路=expense_anchor 所在月份）。**M3 方向定稿：仅追溯方向**（issue 早于 anchor 超期）——未来票由 R-TIME-01 全覆盖，双向判定会对 INJ-TIME-FUTURE 双报误报（对拍真值口径） | n_period=3 | 跨期报销需人工确认 |

- 骨架已交付 **R-ARITH-01 种子实现**（`rules/checks/arithmetic.py`，演示数据全链路用）；R-ARITH-02 的中文大写转换 M3 实现（转换表自带，纯 stdlib）。
- 门控纪律（系列教训迁移）：本项目无文档类目门控问题，但**规则间互斥必须显式**——R-DUP-03 排除已被 R-DUP-01/02 命中的组合，防同一事实双规则重复报（引擎按固定顺序执行并传递已命中集）。

### 3.1 引擎上下文与执行契约（M3 定稿）

| 项 | 契约 |
|---|---|
| 注册顺序 = 执行顺序 | R-DUP-01 → R-DUP-02 → R-DUP-03 → R-SEQ-01 → R-ARITH-01 → R-ARITH-02 → R-TIME-01 → R-TIME-02（DUP 三规则必须在前，R-DUP-03 门控依赖已命中集） |
| run 签名 | `run(cards, ctx_extra=None)`：ctx_extra 合入 ctx，携带 `batch_anchors`（batch_id → ISO 日期映射）、`default_anchor`（无映射时回退的导入日期）、`existing_numbers`（入库前台账既有号码集，R-DUP-01 持久判重输入） |
| R-TIME 双通路 | 基准通路：check 命令 `--anchor-manifest` 读 manifest 批次 expense_anchor（与墙钟无关，seed 可复现前提）；常规通路：不传时 anchor=导入时刻（default_anchor=当天） |
| finding_id | `rule_id + ":" + "|".join(invoice_numbers)`（多号码 finding 号码全集入 ID，保证 findings 表主键唯一；无号码用 "-"） |
| 入库与判重分离 | check 命令流程：解析全部 → 入库（主键拒收同号副本，返回 False）→ 引擎在**全部解析卡**上运行（含被拒副本）→ findings 落库。被拒副本不因拒收而逃过 R-DUP-01/02 判定 |

## 4. SQLite 存储设计

```sql
CREATE TABLE batches (
    batch_id    TEXT PRIMARY KEY,     -- 生成器/导入时间派生
    imported_at TEXT NOT NULL,        -- ISO 时间
    source_desc TEXT DEFAULT '',      -- 来源描述（文件夹名）
    file_count  INTEGER DEFAULT 0,
    log_json    TEXT DEFAULT ''       -- 导入日志（坏文件、跳过原因）
);

CREATE TABLE invoices (
    invoice_number TEXT PRIMARY KEY,  -- 20 位号码（R-DUP-01 依赖主键约束）
    invoice_type TEXT NOT NULL,
    issue_date TEXT NOT NULL,         -- YYYY-MM-DD（字符串序=时间序）
    buyer_name TEXT DEFAULT '', buyer_tax_id TEXT DEFAULT '',
    seller_name TEXT DEFAULT '', seller_tax_id TEXT DEFAULT '',
    amount TEXT NOT NULL, tax_amount TEXT NOT NULL, total_with_tax TEXT NOT NULL,
    total_with_tax_cn TEXT DEFAULT '', remark TEXT DEFAULT '',
    items_json TEXT NOT NULL,         -- LineItem[]
    card_json TEXT NOT NULL,          -- InvoiceCard 全量（含 confidence/field_flags/evidence）
    batch_id TEXT NOT NULL REFERENCES batches(batch_id),
    created_at TEXT NOT NULL
);

CREATE TABLE findings (
    finding_id TEXT PRIMARY KEY,
    rule_id TEXT NOT NULL,
    level TEXT NOT NULL CHECK (level IN ('error','suspicious','review')),
    invoice_numbers TEXT NOT NULL,    -- JSON 数组（可关联多票）
    message TEXT NOT NULL,
    evidence_json TEXT NOT NULL,
    batch_id TEXT,
    status TEXT DEFAULT 'open',       -- open/confirmed/dismissed（人工复核动作，M5 GUI）
    created_at TEXT NOT NULL
);
CREATE INDEX idx_inv_seller_date ON invoices(seller_tax_id, issue_date);   -- R-DUP-03/R-SEQ-01
CREATE INDEX idx_inv_batch ON invoices(batch_id);
CREATE INDEX idx_find_rule ON findings(rule_id, level);
```

- 金额全存 `str`（Decimal 文本），比较在应用层做——规避 SQLite 浮点与区域设置差异。
- `invoices` 主键即 R-DUP-01 的实现基础：二次插入同号触发 ` IntegrityError` → 引擎转 error Finding（而非静默覆盖）。**不 UPSERT 覆盖**——重复导入本身就是异常信号。
- 筛选（FR-07）= invoices 上参数化 WHERE 组装；台账重开持久（NFR）。

## 5. 生成器与真值契约（详见 [05-数据计划与里程碑.md](05-数据计划与里程碑.md) §1）

- 真值按**双键**记录（M1 定稿）：`cards.json` 按文件路径为键（"完美解析"期望卡，同号副本各有内容差异时需两份）；`expectations.json` 按发票号码为键（`expect` + `also_expect`）；基准按"文档全部非 pass 集合"对账——防"只验主期望"的假绿。
- 生成器模块注释即真值语义权威定义（✅ M1 已定稿；同 seed 位级可复现已由守门测试断言，含冻结入仓数据回归）。
