## 一、赛题介绍

随着国家税务总局公告 2024 年第 11 号自 2024 年 12 月 1 日起在全国推广应用**全面数字化的电子发票（数电票）**，发票全面电子化进入收官阶段：数电票取消特定版式，新增 **XML 数据电文格式**（同时保留 PDF、OFD），《发票管理办法》（国务院令第 764 号，2023 修订）明确电子发票与纸质发票具有同等法律效力。企业报销票据随之海量电子化，财务痛点集中爆发：**同一张发票被多名员工重复报销、连号发票拆分报销、票面金额与报销单不符**等问题人工排查慢且易漏。

商业费控 SaaS（报销审批类产品）均为闭源在线服务，**桌面端、离线可用、可复现的开源发票台账工具在 GitHub 上是空白**——尤其是数电票 XML 格式的开源解析器几乎不存在。

本题要求开发一款电子发票智能台账桌面应用：批量导入解析发票文件、本地台账管理、异常检测（重复报销/连号/时间逻辑）、统计看板与 Excel 导出，**全离线运行、规则引擎为主、LLM 可选兜底**。

## 二、任务要求

### 1）发票批量导入与解析

- **输入格式**：数电票 PDF（版式文件文本层）、**数电票 XML（数据电文，2024年11号公告新增格式——本题解析器亮点）**、OFD（可选加分）；拖拽文件夹批量导入；
- **抽取字段**：发票号码（数电票 20 位）、开票日期、发票类型、购买方/销售方名称与纳税人识别号、项目明细、金额、税率、税额、价税合计（含大写）、备注；
- 输出统一中间表示（"发票参数卡"：字段-值-置信度-证据{来源文件，原文摘录}）。

### 2）本地台账管理

- SQLite 本地存储（无上传、无网络依赖）；发票列表增删改查、多维筛选（月份/供应商/类型/金额区间）；
- 统计看板：月度报销额趋势、供应商 Top-N、发票类型分布（QtCharts 或 pyqtgraph 离线渲染）。

### 3）异常检测（核心，规则引擎）

- **重复报销检测**：同一发票号码重复导入（精确）；跨员工/跨批次重复（号码+金额+日期联合键）；金额+日期+销售方近似重复（模糊匹配阈值可调）；
- **连号拆分检测**：同一销售方、同日或邻近日期的连号发票簇（如 88510001~88510005），疑似拆分报销；
- **时间逻辑**：开票日期晚于导入/报销日期、跨期异常；
- **票面算术**：金额+税额=价税合计复核、大小写金额一致性；
- 异常三级判定（确认异常/疑似/待人工确认），每条挂检测规则 ID 与证据。

### 4）导出与报告

- Excel 台账导出（openpyxl，含异常清单 sheet、条件格式标红）；异常检测摘要报告（docx 可选）。

### 5）内置评测基准（零 API 依赖）

- **合成发票生成器**（reportlab 造 PDF + XML 模板直出，固定 seed 可复现）：按发票类型模板批量生成，**程序化植入已知异常**（重复、连号、算术错误、字段缺失）并输出真值 JSON；
- 指标：字段解析 P/R/F1（目标 ≥0.95）、异常检出率 100%、误报率 0；指标表写进 README。

## 六、边界与非目标（防 scope 失控）

- **不做**：真实发票（全部合成，公司名/税号/号码虚构）；OCR 手写/拍照票据（版式 PDF 文本层为主，拍照 OCR 仅作远期加分）；发票验真（不调用税务接口）；报销审批流（**检测辅助定位，非审批决策工具**，报告带免责声明）。
- **隐私红线**：本地 SQLite 存储、无任何网络上传；合成税号用统一社会信用代码假格式（18 位校验位不指向真实主体）并在数据台账注明白名单。
- **品牌隔离**：不复制姊妹项目代码；文档不提建造/电力/医疗/招投标/食品业务。
