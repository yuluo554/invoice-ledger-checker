## 1. 合成发票生成器（M1 核心，FR-30/31）

### 1.1 产物与目录

| 目录 | 内容 | 入仓 |
|---|---|---|
| `data/invoices/` | 生成的发票文件（数电票 XML、版式 PDF、少量 OFD） | ✅ 入仓（合成、无隐私；体积控制在几十 MB 内） |
| `data/ground_truth/` | 配套真值 JSON（卡片期望 + 注入异常期望） | ✅ 入仓 |
| `data/knowledge/` | 法规条文库（原文摘录 + 出处 + status） | ✅ 入仓 |
| `data/samples/` | 手工样例、格式参考样例（含来源登记） | ✅ 入仓 |

### 1.2 生成器设计

- **入口**：`py -m invoice_ledger_checker generate --out data --seed 42 --n 60 --anomaly-rate 0.35`（种子命令入 README；CLI 参数 M1 定稿）。
- **可复现**：`random.Random(seed)` 显式实例（禁全局 random）；同一 seed+参数输出**逐字节一致**（守门测试断言；`.gitattributes` eol=lf 防 CRLF 漂移——风险表 03§5-5）。
- **发票类型模板**：数电普票 / 数电专票 / 电子普票 / 纸质专票 / 纸质普票（5 类，权重可配）；XML 模板直出（ElementTree 构造），PDF 用 reportlab 画版式（标签+值定位绘制，保证文本层可抽取），OFD 直接构造 zip 结构。
- **虚构数据纪律**：公司名从虚构词库组合生成（如"星辰科技/云图商贸"类）；纳税人识别号用假格式统一社会信用代码（18 位，第 17-18 位用白名单占位组合，**不构成真实主体**）并在生成器注释与数据台账登记；发票号码按类型前缀规则合成 20 位。
- **金额结构**：明细 1-5 行，税率取 {0.01,0.03,0.06,0.09,0.13}；金额分位生成保证 Decimal 精确。

### 1.3 异常注入清单（与 [04](04-模块详设.md) §3 规则表一一对应）

| 注入码 | 注入内容 | 主期望（expect） | 隐含期望（also_expect） |
|---|---|---|---|
| INJ-DUP-EXACT | 复制已有发票文件改批次 | R-DUP-01=error | — |
| INJ-DUP-JOINT | 同号同额同日期跨批次副本 | R-DUP-02=error | R-DUP-01=error（同号先触发） |
| INJ-DUP-FUZZY | 同销售方±1日金额差 0 的近似票（不同号） | R-DUP-03=suspicious | — |
| INJ-SEQ | 连号簇 3-5 张同销售方邻近日期 | R-SEQ-01=suspicious | — |
| INJ-ARITH-SUM | 篡改 total_with_tax 使 金额+税额≠合计 | R-ARITH-01=error | — |
| INJ-ARITH-CN | 大写金额与数字不符 | R-ARITH-02=error | — |
| INJ-TIME-FUTURE | 开票日期晚于导入日期 | R-TIME-01=error | — |
| INJ-TIME-STALE | 跨期报销超过 N 期 | R-TIME-02=review | — |
| INJ-FIELD-MISS | 删除必填/常见字段 | 解析层 flag（非异常规则） | 字段 F1 评估中计 FN |
| （基线） | 无注入 | 全部 pass | — |

- **真值语义**（权威定稿见 generator/synthetic.py 模块注释，M1 已落地）：真值按**文件路径**（cards.json，期望卡）与**发票号码**（expectations.json，注入期望）双键记录 `expect: {rule_id: level}` 与 `also_expect: {...}`；基准按**每张卡的全部非 pass 集合**对账——多记了算误报、少记了算漏报，杜绝"只验主期望"假绿。
- 注入互斥坑登记（M1 生成时验证 ✅）：同号副本勿同时注入算术错（R-DUP 先命中后票面已不可复核）——实现为副本一律复制无注入基线卡；连号簇成员间日期窗口与 R-DUP-03 窗口叠加可能双触发——实现为簇内成员金额全局唯一（amount_tol=0.00 下不可能触发），事件成员同批次防锚点漂移。
- M1 定稿补记（与实现的最终出入，均已回填）：
  - **R-DUP-02 排除纯复制件**：联合键相同且跨批次、但两卡字段完全一致（EXACT 副本）只报 R-DUP-01；字段有差异的再制票才报 R-DUP-02（+同号隐含 R-DUP-01）——§1.3 EXACT 行 also_expect="—" 的语义落点，已同步 plan/04 §3；
  - **R-TIME-01/02 时间基准**：基准通路取批次 `expense_anchor`（manifest 固化：batch_01/02/03 = 2026-07-15/08-15/09-15），不依赖墙钟——同 seed 位级可复现的前提；实际使用时为导入时刻；
  - **INJ-ARITH-SUM 数字与大写同步改错**：R-ARITH-02 保持通过、单触发 R-ARITH-01，与 §1.3 表 also_expect="—" 一致；
  - **anomaly_rate 语义** = 注入文件数/总文件数（round 取整）；默认参数下 60×0.35 = 21 文件（9 类注入 + SEQ 簇扩为 5 张）；
  - **真值双键**：cards.json 按文件路径为键（JOINT 再制副本内容不同，需两份期望卡）；expectations.json 按号码为键（规则发现按号码归集）。

### 1.4 法规知识库（data/knowledge/）

- 入库条目格式：`{条文摘录, 规范号, 条号, 渠道, status(已核对/待核对)}`；**无出处不得以确定语气落库**（查证失败 → 显式"待核对"+已查渠道登记，不编造）。
- 已核对锚点（题目阶段）：11号公告（XML 格式）、764号令（电子票同效力）、56号令（实施细则）——全文与条文摘录 M1 获取入库（渠道：国家税务总局法规库 fgk.chinatax.gov.cn）。
- 检测规则的"依据"字段只挂这三部法规+票面自洽逻辑（见 04 §3），**不引申无关条文**。
- 搜索通道污染防线（系列实录）：摘要不采信，只用可直连官方页面原文核验；查不到就标待核对继续推进，不空转。

## 3. 评测基准设计（M4 详设提前定口径）

| 基准 | 输入 | 对账方式 | 指标 | 门槛 |
|---|---|---|---|---|
| 字段解析基准 | 生成器样例集 + 真值卡片 | 真值 dict vs 解析 dict **字段级**（items 展开为 `items[i].field`） | P / R / F1（宏平均 + 分字段表） | F1 ≥ 0.95 |
| 异常检测基准 | 注入样例集 + 真值 expect/also_expect | 引擎 Finding 集 vs 真值非 pass 集（按 发票号码+rule_id 对账；level 不符计错判） | 检出率（TP/真值异常）、误报率（FP/全部告警）、判定准确率（level 一致占比） | 检出率 100%、误报 0 |
| 回归纪律 | — | — | 改数据/改规则/改接口 → 重跑基准确认不回退（既定口径联动） | — |

- 基准**纯规则通路、零 API**（LLM 兜底关闭态）；基准输出落 `benchmarks/report.md`（生成物，README 引用关键表）。
- 基准立起后，"动了会打挂基准"的约定全部显式登记为**既定口径**（真值语义、门槛、InvoiceCard 字段名、规则 ID、engine 签名、门控互斥顺序、eol=lf、测试全离线），写入 HANDOFF 速查区。
