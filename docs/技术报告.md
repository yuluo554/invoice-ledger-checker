# 技术报告：电子发票智能台账与重复报销检测桌面应用

> 项目：invoice-ledger-checker（全离线、规则引擎为主、零 API 依赖）
> 报告对应提交材料"3. 技术报告（解析方案/检测算法/打包与离线设计）"；
> 三大主题之外补数据与评测一节，证据数字全部来自内置基准（可复现命令见文末）。
> 本文档为 docx 版的唯一定稿源：`docs/技术报告.docx` 由 `make_report_docx.py`

## 1. 项目概述

财务报销场景中，电子发票重复报销、跨期报销、票面算术错误是高频风险，而发票
数据散落在报销人手中，企业侧缺乏低成本的核对手段。本项目交付一个 **Windows
桌面应用**：用户将发票文件（数电票 XML 数据电文 / 版式 PDF）按文件夹导入，
程序本地解析入台账（SQLite），用确定性规则引擎做三级异常检测（确认异常 /
疑似 / 待人工确认），并提供台账浏览、多维筛选、看板统计、Excel 导出与
PyInstaller 打包的免安装发行形态。

设计上的三个基点：

1. **全离线**：核心链路（解析 / 存储 / 规则 / 基准）只用 Python 标准库，
   无网络请求、无 API 调用、无 LLM——发票数据不出本机（隐私边界）；
2. **确定性优先**：所有数值结论来自确定性规则，解析不到的字段留空并登记
   标记，不猜值、不造默认值（防幻觉纪律）；
3. **数据先行**：自制合成发票生成器（固定 seed 位级可复现）+ 注入异常真值，
   让"检出率 / 误报率"这类质量指标可零成本重复验证，而不是靠感觉。

## 2. 解析方案

### 2.1 统一中间表示：InvoiceCard 发票参数卡

两类格式、三种解析器（XML / PDF，OFD 为 P2 顺延项）统一产出同一张
**参数卡**：字段-值-置信度-证据四元组（`invoice_number` 主键 + 类型 / 日期 /
买卖双方 / 明细行 / 三级金额 / 大写金额 / 备注）。每张卡携带证据链
（来源文件相对路径 + 原文摘录 + 页码或节点路径），支撑异常判定可溯源。

关键失败语义：**解析不到的字段留空串 + `field_flags` 登记，不造默认值**；
主键（发票号码）缺失的整卡拒绝入库并记导入日志。金额全部用 `Decimal`
文本承载，比较校验在应用层完成，杜绝浮点误差与区域设置差异。

### 2.2 XML 数据电文解析器（数电票）

数电票 XML 是规范化的结构化数据电文，用 stdlib `ElementTree` 解析（默认
不解析外部 DTD，无实体注入面）。核心是一张 **字段映射表**（XML 节点
localname 路径 → 卡字段）：以本地名优先匹配 + 命名空间白名单，ns 不匹配时
降级为纯 localname 匹配并降低置信度。数值清洗（千分位 / 全角 / 货币符）
后做合法性校验，非法即丢弃该值并降置信度。明细行遍历容器节点逐行构造。

### 2.3 版式 PDF 解析器（pdfplumber 文本层）

版式文件的文本层顺序不可靠，采用 **label-slot 槽位规则**：用词级坐标
（`extract_words`）而非字符序，先定位标签词（"发票号码" "价税合计"…），
再按几何关系取右侧 / 下方最近的值槽位。三条实测固化的版式口径：

- **双栏版式截断**：值词以同线下一标签的 x0 为右边界，防止取到邻栏内容；
- **大写合并词**：`价税合计（大写）：` 与值被导出为同一词，取冒号后文本；
- **明细列聚类**：金额 / 税率 / 税额三列按表头 x0 锚点做最近列归并，
  逐行聚合成明细行。

### 2.4 解析质量：字段级基准对账

解析质量用字段级 P/R/F1 度量（明细行展开为 `items[*].字段`；空对空计
正确；证据 / 置信度等元数据不参与）。冻结 60 份合成票（XML 35 / PDF 22 /
OFD 3 顺延）实测 **微平均 = 宏平均 F1 = 1.0000**（门槛 ≥ 0.95），且逐文件
判定与独立对账器实现互为断言，防两套口径漂移。

## 3. 检测算法

### 3.1 八规则体系与三级判定

检测全部由确定性规则引擎完成，八条规则按固定顺序执行（重复类在前，
模糊规则的门控依赖精确规则的已命中集）：

| 规则 ID | 名称 | 级别 | 逻辑要点 |
|---|---|---|---|
| R-DUP-01 | 精确重复 | error | 批内同号多卡，或号码已存在台账（跨运行持久判重） |
| R-DUP-02 | 联合键重复 | error | 同号同额同日期跨批次再制票；排除字段全等的纯复制件（由 01 覆盖，防双报） |
| R-DUP-03 | 模糊重复 | suspicious | 同销售方 ± 日期窗口内金额差 ≤ 阈值的近似票（排除已命中号） |
| R-SEQ-01 | 连号拆分簇 | suspicious | 同销售方号码后缀连续 ≥3 张且日期在窗口内（跨前缀不产出，防误报） |
| R-ARITH-01 | 价税合计复核 | error | Σ明细 = 金额 且 金额+税额 = 价税合计（容差 0.01；字段缺失跳过不硬判） |
| R-ARITH-02 | 大写金额一致 | error | 大写金额与数字价税合计互核（自带中文大写转换） |
| R-TIME-01 | 开票晚于导入 | error | 开票日期晚于批次基准日（未来票） |
| R-TIME-02 | 跨期异常 | review | 报销基准月前追溯超过 N 期（仅追溯方向——未来票由 01 全覆盖，防双报） |

三级判定语义：`error` = 确认异常（确定性算术 / 键冲突）；`suspicious` =
疑似（模糊 / 簇类启发式）；`review` = 待人工确认（跨期临界）。每条 finding
挂规则 ID、证据与关联发票号码，多号码 finding 的号码全集进入主键。

### 3.2 两个关键工程决策

- **入库与判重分离**：检测引擎的输入是全部解析卡（含即将被台账主键拒收的
  同号副本）。被拒副本不因拒收而逃过 R-DUP-01/02 判定——重复导入本身就是
  异常信号，重复导入同一批文件会把全部号码判为精确重复，这是特性而非缺陷。
- **R-TIME 双通路时间基准**：基准评测通路从 manifest 读批次报销基准日
  （与墙钟无关，同 seed 位级可复现的前提）；实际使用通路默认取导入时刻。
  引擎禁用墙钟兜底——缺锚点映射是基准的门槛失败项，不是静默回退。

### 3.3 检测质量：注入真值对拍

生成器在 60 份合成票中注入 9 类已知异常（复制件 / 联合键再制 / 近似票 /
连号簇 / 两类算术错 / 两类时间错 / 字段缺失），真值按"发票号码 × 规则 ID"
全集记录（含注入隐含的次生期望，防"只验主期望"假绿）。冻结数据实测：
**检出率 100%（18/18 对）、误报率 0%、判定准确率 100%**，八条规则全部
有触发形态。

## 4. 数据先行与可复现性

- **合成生成器**：唯一随机源 `random.Random(seed)`，同参数重跑逐字节一致
  （守门测试断言，含 EOL 门）；发票类型 5 种 × 三格式；公司名 / 税号 /
  发票号码全部虚构（税号为假格式自证虚构，不含任何真实主体）。
- **真值三件套**：期望卡（按文件路径）、注入期望（按号码）、批次锚点
  manifest，随冻结数据入仓；改生成器必须重跑生成命令整目录刷新。
- **确定性报告**：基准报告无时间戳 / 路径 / 环境信息，同输入重跑逐字节
  一致（测试守门），报告作为生成物入仓供比对。
- **法规依据**：检测规则的"依据"字段只挂票面自洽逻辑与已核对法规
  （764 号令 / 56 号令实施细则 / 11 号公告）；三部法规原文均逐字核对入库
  （条号 + 渠道 + 核对日期，见 `data/knowledge/`），条目以"要点"前缀标识的
  未核对内容一律标"待核对"、不以确定语气落库。核对中发现并订正了两处
  登记偏差：11 号公告官方标题无"的"字；其正文与附件**不含** XML 格式条款
  （"取消特定版式、增加 XML 数据电文格式"出自官方解读口径而非公告条文，
  引用时回避条号）。11 号公告第四条经核对确认 20 位号码法定分段
  （2+2+1+15），与合成生成器的号码布局结构一致。

## 5. 打包与离线设计

### 5.1 依赖分层与 extras

`pyproject` 核心依赖为空：模型 / 存储 / 规则 / 引擎只用标准库；重量级库
全部走 optional extras（parse=pdfplumber、data=reportlab、export=openpyxl、
desktop=PySide6(+Addons)、report=python-docx、pack=PyInstaller），运行期
经 `import_optional` 惰性导入，缺依赖时给出带安装提示的报错而非裸崩。
extras 与运行期真实 import 的覆盖关系由回归测试静态锁声明
（tests/test_extras.py），缺声明即测试红。

GUI 兼容性实测：Python 3.8 下 PySide6 6.7+ 不再发 cp38 wheel，extras 锁
`>=6.5,<6.7`（实测 6.6.3.1 为该区间最新可用版）；QtCharts 位于
PySide6-Addons，作为独立依赖显式声明。

### 5.2 PyInstaller onedir 双 exe

- 主 `.spec` 入仓（可复现构建）：onedir 模式产出一个发行目录，含
  **双 exe** ——`invoice-ledger.exe`（GUI，无控制台，双击即用）与
  `invoice-ledger-cli.exe`（控制台），后者使无 Python 机器也能脚本化
  验证全链路（doctor / demo / generate / check / export / benchmark）。
- GUI 入口带 **崩溃兜底**：初始化异常写日志到 exe 旁（只读时退回临时
  目录）并弹原生消息框，不闪退。
- **冒烟探针**：环境变量 `INVOICE_LEDGER_GUI_SMOKE=1` 时窗口显示 1.5 秒
  自动退出，支持无人值守验证 GUI 可启动。
- datas 白名单为空：运行期不需要仓库内数据（demo 自含合成数据），版权
  红线数据一律不入包；构建后守门测试遍历产物树断言无禁区成分。
- 打包纪律测试双守门（spec 形态静态断言 + 产物树断言）随全量测试运行。

### 5.3 离线与隐私边界

安装后运行全程无网络请求；台账为单文件 SQLite，删除即销毁；导出的
Excel / 报告只落用户指定路径；状态栏常驻免责声明（检测结论仅供人工
复核参考，不构成审计意见）。

## 6. 桌面应用形态

PySide6 多页签六组件，**只消费既有 CLI / 引擎 API，不另起第二套行为**：

导入向导（文件夹导入 → 批次摘要 + 坏文件清单）/ 台账表格（多维筛选 +
分页 + 增删改查；编辑仅开放联系人字段，号码 / 金额为对账链字段只读）/
异常清单（按级别着色 + 证据面板原文摘录 + 双击详情 + 复核状态动作）/
看板（QtCharts 月度趋势双折线 / 供应商 Top-N 柱形 / 类型分布饼图）/
导出（Excel 双 sheet + 条件格式按级别标红）/ 设置（数据库路径 + 七项
检测参数，默认值与规则模块常量同源）。

## 7. 质量保障

- 测试 166 项全绿（stdLib+pytest 分层，重依赖缺失显式 skip 计数上报，
  收集数在干净 venv 与 dev 环境强制一致）；GUI 测试 offscreen 常驻、
  模态对话框全部屏蔽；
- CI 四作业：test（win3.8 / win3.12 / ubuntu3.12）+ benchmark
  （win3.8 装全 extras 跑基准门槛断言），门槛未达即回归信号；
- 基准不回退纪律：改数据 / 规则 / 引擎 / 接口必须重跑基准，"动了会打挂
  基准"的约定全部显式登记为既定口径。

## 8. 限制与边界（如实声明）

- OFD 格式为 P2 顺延项：导入时显式登记顺延清单，不参与指标对账
  （真值侧无对应期望，无结构性缺口）；
- 全部演示与评测数据为程序合成虚构，不含任何真实主体或真实票据；
- 检测结论为规则引擎输出，供人工复核参考，不构成审计意见；
- 版式 PDF 解析依赖文本层（非扫描件）；本项目样例均为程序生成的
  可抽取版式。

## 9. 复现命令

```bash
# 环境：Python >= 3.8；pip install -e ".[all]" 装全可选依赖
py -m invoice_ledger_checker demo                       # 端到端演示（合成数据，内存库）
py -m invoice_ledger_checker generate --out data --seed 42 --n 60
py -m invoice_ledger_checker benchmark                  # 双基准 + 门槛断言（报告逐字节可复现）
py -m pytest                                           # 全量测试
pyinstaller packaging/invoice_ledger_checker.spec       # onedir 双 exe 打包
```
